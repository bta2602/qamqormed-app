# Asem-Ai: Google Gemini

Обновлено 9 ноября 2026 года. По решению владельца Asem-Ai возвращён на Gemini.
Подключение Groq/Qwen удалено из рабочего кода. Отзыв прежнего Google-ключа
подтверждён владельцем; для этого подключения используется новый ключ.
Владелец прислал успешный результат `Test-Gemini.ps1`: модель
`gemini-3.5-flash-lite`, `synthetic_completion_received`, 1346 мс.
Новый ключ не выводился. Наличие `GEMINI_API_KEY` в Netlify Production
подтверждено, но это не проверка запроса через опубликованный API.
В Production отсутствуют ключи шифрования БД, и старые записи ещё не зашифрованы:
см. [RELEASE-READINESS-2026-11-09.md](RELEASE-READINESS-2026-11-09.md).
Neon не заменяется; отдельная SQL-миграция для смены ИИ не нужна.

## Ключ и Netlify

1. Создайте новый ключ в [Google AI Studio](https://aistudio.google.com/apikey).
   Используйте проект, предназначенный для QamqorMed. Не восстанавливайте
   отозванный ключ из истории Git и не присылайте новый в чат.
2. В Netlify откройте проект сайта: Project configuration > Environment variables.
3. Создайте или обновите **GEMINI_API_KEY**. Значение: новый ключ без кавычек.
   Включите **Contains secret values**, задайте значение только для **Production**.
   Если выбор scopes доступен, нужен **Functions**. Сборке этот ключ не требуется.
4. Необязательная переменная **GEMINI_MODEL**: `gemini-3.5-flash-lite`.
   Если она отсутствует, используется именно эта модель. Если осталась старая
   GEMINI_MODEL, проверьте её: она имеет приоритет над значением по умолчанию.
   Доступность модели и квоты своего проекта проверяйте в AI Studio.
5. **GROQ_API_KEY больше не используется**. Если он был создан только для QamqorMed,
   удалите переменную Netlify и отзовите ненужный ключ в Groq. Не удаляйте ключи
   других проектов, переменные Neon, сессий и шифрования.

Рабочий ключ не нужен в Deploy Previews, Branch deploys, Preview Server & Agent
Runners, Local development, HTML, Android, Gradle, SQL или netlify.toml.
Для доверенной тестовой среды используйте отдельный ключ. Секреты Netlify нельзя
прочитать обратно после сохранения; храните собственную копию в менеджере паролей.

Сохранение переменной само по себе не обновляет опубликованные функции. Новая
публикация разрешается после проверок ниже; не запускайте её только ради ключа.
Источники: [ключи Gemini](https://ai.google.dev/gemini-api/docs/api-key),
[окружение Netlify](https://docs.netlify.com/build/environment-variables/get-started/).

## Что делает приложение

- Сайт/Android обращаются к Netlify, Netlify обращается к Google по HTTPS.
  Ключ передаётся только сервером в `x-goog-api-key`, не в URL, ответе или логах.
- Модель задаётся сервером; клиент не может выбрать адрес провайдера или модель.
- Перед отправкой пользователь подтверждает Google Gemini. Версия согласия:
  `google-gemini-v2`. Прежнее согласие Groq и старое неверсионированное согласие
  не принимаются. Нужно обновить сайт и APK; обычный чат с врачом не изменён.
- Отправка ИИ остаётся на `/.netlify/functions/ai-chat`; чтение истории и чат
  с врачом на `chat`. Старый сервер без нового маршрута вернёт ошибку; нет
  автоматического перехода на прежний маршрут или другого провайдера.
- Google получает текущий текст и до 10 предыдущих сообщений этого диалога.
  ИИН, email и другие поля аккаунта не добавляются в запрос. Введённые самим
  человеком сведения в тексте могут попасть к Google: это не обезличивание.
- Общий текст ограничен 24 000 байт UTF-8, не токенов; ответ ограничен 2048
  выходными токенами. Таймаут 20 секунд. Нет автоматических повторов при 429.
- Заблокированные, обрезанные, пустые ответы и вызовы инструментов не выдаются
  как успешный ответ. Внутренние рассуждения не показываются и не сохраняются.
- Проверки сессии, прав доступа и ключей шифрования выполняются до передачи ИИ.
  Успешная пара сообщений сохраняется зашифрованной; сбой сохраняет черновик
  у пользователя, но не создаёт ложного ответа в истории.

## Ограничения использования

Бесплатный Gemini использует ввод и ответы для улучшения продуктов; возможна
проверка людьми. Не отправляйте реальные персональные, медицинские или
конфиденциальные данные. Сейчас владелец подтвердил только вымышленные данные.
Шифрование базы Neon не скрывает переданный текст от Google.

Asem-Ai в этой конфигурации является справочным помощником по приложению,
не клиническим сервисом: не диагностирует, не назначает лечение и не
интерпретирует индивидуальные анализы. Условия Gemini API ограничивают
клиническое применение и медицинские советы. Платный режим меняет обработку
данных, но сам по себе не разрешает запрещённое применение.
Источник: [Gemini API Terms](https://ai.google.dev/gemini-api/terms).

## Проверка без публикации

Один технический запрос без данных пациентов и доступа к БД:

```powershell
& 'C:\AndroidProjects\qamqormed-app\scripts\Test-Gemini.ps1'
```

Введите новый ключ в скрытый запрос скрипта. Не вставляйте ключ в команду,
историю терминала или чат. Скрипт временно передаёт его дочернему Node.js
через окружение процесса, не сохраняет на диск и восстанавливает прежнее
окружение в finally. Это не защита от вредоносного ПО на самом компьютере.
При запрете запуска политикой компьютера не отключайте системную защиту.

Результат JSON не содержит ключа, текста ответа или диагностики Google:

- `passed`: получен полный ответ с контрольной фразой;
- `blocked`: отсутствует ключ или некорректно задана модель, запрос не отправлен;
- `rate_limited`: HTTP 429; смотрите квоты в AI Studio, не запускайте в цикле;
- `provider_or_network_unavailable`: проверьте модель, ключ, доступ и сеть;
- `unexpected_test_reply`: ответ получен, контрольная фраза не совпала.

При 429 выводятся retryAfterSeconds и retryAfterSource. Источник `provider`
означает Retry-After провайдера; `fallback` означает запасное ожидание, не
обещание восстановления квоты. Лимиты проекта смотрите в
[AI Studio](https://aistudio.google.com/rate-limit).

Если ключ уже передан доверенным окружением, используйте `npm run ai:check`.
Реальный запрос не включён в тесты и сборку. Успех локального теста не доказывает,
что в Netlify сохранён тот же ключ или опубликована актуальная функция.

## Публикация

1. `npm run verify:local`: тесты с подменённым транспортом, скан секретов, сборка.
2. Закрыть оставшиеся блокеры из [отчёта](RELEASE-READINESS-2026-11-09.md) и
   [инструкции защиты данных](DATA-PROTECTION-RU.md). Смена ИИ не отменяет
   проверки схемы, шифрования и восстановления доступа.
3. Не отключать `build:netlify`: он проверяет БД на чтение до публикации.
4. После согласованной публикации проверить новый API с вымышленным аккаунтом
   и обновлённым APK, включая отказ без согласия и сохранение черновика при сбое.
